# Phase 05.4 Plan 04: Runtime environment renderer (ENV) Summary

**`js/environment.js` — a pure, deterministic, seeded layout engine (floor tiles, architecture, props, decals, obstacle/hazard skins, lights/atmosphere) plus a Pixi build/sync layer, wired into `renderBackground`/`renderObstacles` behind a `typeof ENV` guard, with a three-tier fallback (real manifest → legacy-bg-as-tile kit → untouched legacy primitives) verified in headless Chrome via a new `tools/art/env_shots.mjs`.**

## 05.1 contract answers (recorded per Task 1 instructions)

**(a) Where arena sizes live (normal/boss):** `DATA.ARENA.sizes = { combat: {w:2240,h:1300}, boss: {w:1600,h:960}, rest: {w:1180,h:580} }`, with a fixed `origin: {x:50,y:84}`. `ROOMS.setArena(kind)` mutates `GAME.arena` **in place** (`Object.assign`), so any code holding `const A = GAME.arena` (including ENV's `layout()` caller) sees live values.

**(b) Does the camera clamp expose a padding/world rect?** Yes. `DATA.ARENA.padBySize = { combat: {l:120,r:120,t:200,b:110}, boss: same, rest: {l:50,r:50,t:84,b:56} }`. `ROOMS.setArena` sets `GAME.arenaPad` from this table; both `CAMERA.pad()` (feeding the scroll clamp *and* the follow anchor) and `ROOMS.worldRect()` (`= CAMERA.worldRectFor(GAME.arena, GAME.arenaPad)`) read the same value — so ENV's `frameRect()` (which uses the same formula, `ENV.pad()` converting `{l,r,t,b}` → `{top,side,bottom}`) always matches exactly what the camera can actually scroll to reveal. Top pad (200) is comfortably above `ENV.CFG.FACE_MIN` (60) — no "padding too small" degradation triggers on combat/boss rooms today.

**(c) How the world bridge canvas maps to world coords now:** `CAMERA.begin()` computes `{tx,ty,tz}` once per frame (`screen = world*tz + (tx,ty)`), unconditionally sets `worldContainer.position/scale`, and counter-transforms `bridgeSprite` (`position = (-tx/tz,-ty/tz)`, `scale = 1/tz`) so the 1280x720 bridge canvas — drawn in world space via `CAMERA.applyCtx(ctx)` — lands pixel-identical to Pixi children. ENV's Pixi layers (`floorLayer`/`lightLayer`/`structLayer`/`atmosLayer`) are ordinary children of `worldContainer`/`bgContainer`, so they ride the exact same transform with zero extra code.

**(d) Did renderBackground's outer-dim/wall-stroke code move?** No — still in `renderBackground` at the same call site, just parameterized on 05.1's world rect (`_bgRect()`/`CAMERA.viewRect(40)`) instead of hardcoded 1280x720 literals. This plan wrapped those exact regions in `if (!envOn) { ... }` without relocating any of them, so `git diff js/game.js` touches only `renderBackground`/`renderObstacles`.

## Layer order as implemented (matches 05.4-CONTEXT D-02 exactly)

```
app.stage:        [ worldContainer, ENV.vignette (screen-space), hudContainer ]
worldContainer:   [ ENV.floorLayer, SPRITES.bridgeSprite, SPRITES.bgContainer{ENV.lightLayer, ENV.structLayer},
                     SPRITES.entityContainer (+ y-sorted prop/pillar-skin/wall-skin items), ENV.atmosLayer, SPRITES.fxContainer ]
```

`floorLayer` is inserted via `addChildAt(floorLayer, worldContainer.getChildIndex(bridgeSprite))` so it sits directly below the bridge (and below the hidden legacy `bgSprite`). `lightLayer`+`structLayer` are appended to `SPRITES.bgContainer`, which already sits above the bridge. `atmosLayer` is inserted immediately after `entityContainer`. The screen-space vignette sprite is inserted into `app.stage` at index 1 (between `worldContainer` and `hudContainer`).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `ensureLoaded()` permanently cached `'unavailable'` on a real load race**
- **Found during:** Task 3, first `env_shots.mjs` run against naraka + vaitarani — `stats.json` showed `env: null` for every naraka shot (ENV never activated) while every vaitarani shot had real stats.
- **Root cause:** `_loadBiome()`'s fallback branch reads `SPRITES.textures['bg:'+biomeId]`, which is populated by `SPRITES.load()` — a separate, independently-timed async call at boot. Naraka is entered almost immediately after `btn-begin` is clicked (well before its texture atlas necessarily finishes loading), so the very first `ensureLoaded('naraka')` call could see `!legacyTex` and permanently cache `_biomeStatus['naraka'] = 'unavailable'` — a race, not a genuine "no art available" case. Vaitarani, entered many seconds later in the same session after several other rooms/shots, never hit the race because its texture had long since finished loading.
- **Fix:** when the legacy texture isn't ready yet, `_loadBiome` no longer caches a terminal status — it `delete`s the (transient) status entry and sets a 300ms retry gate (`_retryAt[biomeId]`), so `ensureLoaded` reports `'loading'` and tries again shortly, resolving to `'fallback'` once the texture lands (same terminal outcome as before, just no longer racy).
- **Files modified:** `js/environment.js`.
- **Verification:** re-ran `env_shots.mjs --biomes naraka,vaitarani` — all 14 shots now report real `ENV.stats()` (previously naraka's 7 shots reported `null`). `node test/smoke.js` still green throughout (the bug never affected the pure/headless invariant sweep, only the browser-only load path).
- **Committed in:** `d2e90da` (Task 3 commit — found and fixed before that commit; no broken version of `env_shots.mjs` was ever separately committed).

**2. [Rule 3 - Blocking, tooling substitution] `tools/art/review_grid.py` does not exist yet**
- **Found during:** Task 3 — the plan's action text says "Build per-biome review grids with `tools/art/review_grid.py --cell 480 --cols 3` and Read them."
- **Issue:** that script belongs to the still-pending 05.4-01/02/03 art plans (per this plan's file-ownership list, `tools/art/**` outside `env_shots.mjs` is out of this plan's scope to create), and does not exist in this worktree yet.
- **Fix:** substituted direct `Read` of the individual PNG screenshots (naraka NW/SE/combat/boss, vaitarani center/boss) for the same visual review goal — confirmed floor coverage with no black gaps, correct architecture framing, visible door glyphs/reward labels, correct `@abyss` pit fallback, visible hazard telegraph, clean boss-arena rendering. No code changes resulted from this substitution beyond the Rule-1 bugfix above.
- **Files modified:** none (verification-only).
- **Committed in:** n/a (documented here; not a code change).
