## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Chamberlin SVF bandpass produced non-finite samples for bright noise transients**
- **Found during:** Task 2 (metal ching/chak, and other high-frequency noise transients)
- **Issue:** The initially-implemented state-variable bandpass filter for band-limited noise transients (`addNoiseTransient`) is only conditionally stable, and became numerically unstable (producing `NaN`/`Infinity`) once its center frequency (5-12kHz for metal/Ta transients) approached a large fraction of the 32kHz render Nyquist.
- **Fix:** Replaced it with a cascade of two one-pole filters (lowpass at `hi`, then subtract a further lowpass at `lo`), which is unconditionally stable for any cutoff below Nyquist.
- **Files modified:** `js/music.js`
- **Commit:** `2a8b33e`

**2. [Rule 1 - Bug] ks() plucked-string tuning was off by up to ~49 cents**
- **Found during:** Task 2 (the ks(220/440/880Hz) autocorrelation tuning smoke test)
- **Issue:** The originally-drafted first-order allpass fractional-delay stage (Jaffe-Smith-style) did not deliver the nominal fractional delay it was designed for at the fractional remainders this code actually produces, leaving every tested pitch 12-49 cents sharp.
- **Fix:** Replaced the allpass with a rounded integer delay-line length (empirically calibrated with a +1 sample correction for this implementation's specific read-before-write ordering), verified by direct autocorrelation measurement to land every tested frequency within 10 cents (max observed ~6 cents).
- **Files modified:** `js/music.js`
- **Commit:** `2a8b33e`

**3. [Rule 1 - Bug] Riser/swell and Dha/Dhin composite bols failed click-free/peak invariants**
- **Found during:** Task 2 (generic per-render invariant checks)
- **Issue:** (a) `bol('Dha'/'Dhin', ...)` mixed two already-normalized sub-renders without re-normalizing the sum, producing peaks above 1.0; (b) riser/swell's linear tail fade wasn't steep enough near the very last samples to bring a *rising* envelope's tail below the required near-silence threshold.
- **Fix:** (a) wrapped the Dha/Dhin mix in the shared `finishBuf` pipeline; (b) changed the shared fade-out curve from linear to cubic (steeper right at the boundary) and increased riser/swell's tail-fade duration.
- **Files modified:** `js/music.js`
- **Commit:** `2a8b33e`

**4. [Rule 1 - Bug] Several hot loops exceeded the 50ms per-job / 800ms per-bank render budgets**
- **Found during:** Task 2 (performance smoke test)
- **Issue:** `membraneTonal`'s bend case, `bell`, `stab`, and `riser` each called `Math.sin`/`Math.exp`/`Math.pow` once (or several times) per sample, which measured far slower than expected once actually run inside the vm sandbox the smoke tests use (a >10x slowdown vs. the identical code run directly in Node, confirmed by isolated benchmarking) — `nagara`, `riser`, and occasionally other jobs exceeded 50ms.
- **Fix:** Replaced per-sample transcendental calls with rotating-phasor recurrences and recursive multiplicative envelope decay wherever the frequency is piecewise-constant (including block-updating riser's continuously-swept frequencies once per 128 samples), and switched the perf test itself to a JIT-warmed, min-of-3-samples measurement (a single sample was occasionally caught by an unrelated GC pause, flagging a different job almost every run).
- **Files modified:** `js/music.js`, `test/smoke.js`
- **Commit:** `2a8b33e` (synthesis fixes), `d2b2f54`/local commit history covers the perf-test refinement made alongside Task 2's own commit (folded into `2a8b33e`)

### Test-only fixes (no production code change)

- The "polling contract" test originally asserted `snapshot(GAME).state === 'hub'` at whatever point in the file the new section happened to run, but many earlier smoke sections leave `GAME` mid-run by the time execution reaches the end of the file. Fixed by re-booting (`META.load(); GAME.init(); UI.hub();`) immediately before that specific assertion, which is what "at boot" actually means for a contract test placed at the end of the suite.
- `Float32Array`/typed-array return values from `MUSIC.dsp`/`MUSIC.dsp.impulse` serialize to plain numeric-keyed objects (not arrays) under `JSON.stringify` across the vm boundary; several helper call sites were missing an explicit `Array.from(...)` wrapper, causing `TypeError: samples.every is not a function`. Fixed by wrapping every typed-array extraction point.
- The "10 calls at once -> exactly CAPS.tabla succeed" `playOneShot` cap test initially ran immediately after an earlier one-shot on the same stem that hadn't finished yet, silently consuming one of the 6 tabla voice slots and making the expected-successes count off by one. Fixed by advancing the mock clock past that earlier one-shot's duration before starting the cap test.

## Issues Encountered

Code executed inside `vm.runInContext` measured consistently and substantially slower (>10x in isolated benchmarking) than identical code run directly in Node for hot per-sample synthesis loops. This is a property of the Node `vm` module's context isolation, not of the production code (which will run in a real Electron/browser main realm, not a `vm` sandbox, once shipped) — but since the smoke-test harness is itself `vm`-based, several DSP functions needed the hot-loop optimizations described above purely to satisfy the test environment's own render-time budget with a comfortable margin.
