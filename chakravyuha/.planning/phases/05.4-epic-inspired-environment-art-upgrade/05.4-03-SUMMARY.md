## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `merge_manifest()` silently dropped every tile/frame not included in a partial `--only` rebuild**
- **Found during:** the orchestrator-requested Ranabhoomi redo (chariot_wreck/fallen_banner/column), first `--only` rebuild attempt
- **Issue:** `finish_env.py`'s `merge_manifest()` built the merged `tiles`/`frames` sections by iterating only the freshly-built `new` manifest's keys. A partial build (`env_build.py ranabhoomi --only chariot_wreck,fallen_banner,column`) produces a `new` manifest whose `tiles`/`frames` are a strict subset (just the 3 rebuilt subjects), so the written manifest collapsed from 4 tiles/14 frames to 0 tiles/3 frames -- every untouched subject (including both floor tiles, wallface, wallcap, and 11 other props/decals) vanished from the manifest.
- **Fix:** Rewrote the tile/frame merge loop to iterate the union of existing+new section keys; an existing key absent from `new` is now carried forward unchanged (deep-copied), while a key present in `new` is merged/overwritten exactly as before.
- **Files modified:** `tools/art/finish_env.py`
- **Verification:** A standalone synthetic before/after check (hand-built existing/new dicts, asserted untouched entries survive and rebuilt entries update) plus a real before/after entry-count comparison on the actual Ranabhoomi rebuild (4 tiles/14 frames before -> 4 tiles/14 frames after, vs. 0 tiles/3 frames with the buggy version); `finish_env.py --self-test` (all 5 existing cases) still passes; `node test/smoke.js` and `node tools/check-provenance.js` green after the real rebuild.
- **Committed in:** `63a86c8`

**2. [Rule 1 - Bug] Own mistake: `fallen_banner.accepted_attempt` set to the old rejected seed instead of the new corrected one**
- **Found during:** the same Ranabhoomi redo, immediately after the first (buggy) `--only` rebuild, when `git status` showed `fallen_banner`'s raw frame file as unchanged despite a brand-new generation having been accepted
- **Issue:** After reviewing the new `fallen_banner` generation (seed 63093, attempt 3) and writing its `self_review`, `accepted_attempt` was mistakenly set to `0` (the old, orchestrator-rejected umbrella-shaped seed 63090) instead of `3`.
- **Fix:** Corrected `accepted_attempt` to `3` before re-running the (by-then-fixed) partial rebuild.
- **Files modified:** `tools/art/prompts.json`
- **Verification:** `git diff --stat` on the rebuilt frame confirmed the file content changed (52409 -> 94715 bytes) after the fix, matching the newly-reviewed banner image.
- **Committed in:** `63a86c8`

**3. [Rule 2 - Missing functionality] `finish_env.py` lacked a matte-selection option for prop cutouts**
- **Found during:** Task 1 start, per orchestrator guidance to use `birefnet-general` for thin-detail Ranabhoomi/Vaitarani props
- **Issue:** `finish_env.py`'s `prop_finish()` hard-called `fsprite.load_and_cutout(in_path)` with no way to select a non-default rembg model, even though `finish_sprite.py` (used by the god-portrait and character pipelines) already supported `--matte u2net|isnet-general-use|birefnet-general` per the 05.5-04/05.6-03 bake-off.
- **Fix:** Added a `matte="u2net"` parameter to `prop_finish()`/the CLI's `prop` subcommand (default preserves byte-identical behaviour for every existing caller), and `env_build.py` now reads `entry.get("matte", "u2net")` per subject to pass through.
- **Files modified:** `tools/art/finish_env.py`, `tools/art/env_build.py`
- **Verification:** `finish_env.py --self-test` (prop mode case) still passes with the default; birefnet-general-selected subjects (dhvaja, gate, chariot_wheel, etc.) reviewed clean on checker background with thin detail (banner poles, wheel spokes, arrow shafts) intact.
- **Committed in:** `aa09f32` (mechanism), used throughout both biome commits
