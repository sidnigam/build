# Phase 2 — UI Design Contract

> Visual and interaction contract for the Asset Pipeline + Sprite System phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This is a game-canvas UI, not a web/component UI. There is no DOM component library, no React/Vite/Next, and therefore no shadcn (gate not applicable — see Design System below). The "UI" governed here is the **on-canvas illustrated art direction**: player/enemy/boss sprites, biome backgrounds, and the canvas-drawn HUD / boon-card / overlay art (ART-05). The spacing/typography/color tables below codify the *existing* in-game visual identity already present in `js/data.js` and `js/game.js`, which Phase 2's illustrated assets MUST stay consistent with. PixiJS replaces the Canvas 2D renderer (D-02) but the visual identity does not change.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla JS HTML5 game; shadcn gate N/A — not a React/Next/Vite project) |
| Preset | not applicable |
| Component library | none — on-canvas rendering via PixiJS 8 (D-01/D-02), sprites loaded from atlases |
| Icon library | none — Indian motif glyphs are part of the illustrated UI atlas (ART-05); legacy Unicode symbols (✦ ¤ ॐ ♥ ◈ ☽ ⚖ ☠) used in fallback path only (`DATA.REWARDS`, `js/data.js`) |
| Font | **Georgia** (serif) — established in `js/game.js` (all `ctx.font` calls). Pre-existing; do not change in this phase. Any baked-in lettering in UI-atlas art (boon card titles, overlay headers) should read as the same warm serif character. |

**Art direction (the core visual contract for this phase):**

- **Style:** Hades-adjacent **illustrated 2D** with strong, readable silhouettes. NOT pixel art. (CONTEXT specifics)
- **Tone:** Warm earth tones, Indian mythology motifs; mythological reverence — gods are allies, asuras/rakshasas oppose the player (CLAUDE.md constraint).
- **Visual anchor:** The **Abhimanyu reference sheet** is generated, locked, and human-approved FIRST; all other characters derive from the same locked ComfyUI workflow + reference-as-ControlNet (D-07). Style drift is a regenerate condition (RESEARCH Pitfall 5).
- **Silhouette test:** Every character sprite must be identifiable as a black silhouette — this is the gsd-ui-checker / human-review pass criterion for Dimension 2 (Visuals).

## Sprite Dimension Contract

> Hard pixel contract for the art pipeline and atlas packer. Source frame sizes (D-08); not part of the 4/8 spacing scale (game-asset sizing is a separate axis — see Exceptions).

| Asset class | Source frame | Notes |
|-------------|--------------|-------|
| Player (Abhimanyu) | 128×128 | 4+ states: idle 4f, run 6f, attack 5f, dash 4f (discretion start; expand if quality allows) |
| Enemies (8 archetypes) | 128×128 | preta, rakshasa, archer, naga, vetala, bhuta, daitya, yatudhana (`DATA.ENEMIES`) |
| Bosses (4) | 256×256 | tataka, ahiravana, kumbhakarna, yama — plus a **phase-2 art variant** per boss (alternate palette / enraged form; art asset only, trigger logic is Phase 4) |
| Biome bg / floor (4) | 512×288 | naraka, patala, ranabhoomi, vaitarani — full-scene images, NOT atlased (D-10) |
| UI atlas | packed | boon cards, HUD elements, overlay panels with Indian motifs (ART-05) |

Atlas budget: 2048×2048 max per atlas; padding 2px; no rotation; trim on (RESEARCH Code Example 2). `anchor.set(0.5)` for centered character sprites.

## Spacing Scale

Declared values (must be multiples of 4) — for any new canvas-drawn UI chrome (HUD bars, boon-card padding, overlay panel insets):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline gaps, bar borders, glyph-to-text gaps |
| sm | 8px | Compact HUD element spacing, boon-card internal padding |
| md | 16px | Default spacing between HUD groups / overlay rows |
| lg | 24px | Overlay panel padding, section gaps |
| xl | 32px | Major layout gaps between HUD clusters |
| 2xl | 48px | Overlay header-to-body break |
| 3xl | 64px | Full-screen overlay margins |

Exceptions:
- **Sprite frame sizes (128 / 256 / 512×288)** are a game-asset sizing axis, not UI chrome spacing — they are NOT required to fall on the 4/8 token scale beyond being even pixel dimensions. Documented in the Sprite Dimension Contract above.
- Boss sprites render at up to 256×256 source on a ~800×600 / 1280×720 canvas (scaled per biome `scale` factor 1.0–2.1 in `DATA.BIOMES`).

## Typography

Established in-game type ramp (from `js/game.js` `ctx.font` calls; Georgia throughout). Declared as exactly 4 sizes / 2 weights to satisfy the type-discipline contract. Any lettering baked into UI-atlas art must match this ramp visually.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (boss name / title) | 22px | bold (700) | 1.2 |
| Heading (boon card title / overlay header) | 16px | bold (700) | 1.2 |
| Body (boon description / overlay copy) | 14px | regular (400) | 1.5 |
| Label (HUD counters, costs, small captions) | 12px | bold (700) | 1.4 |

Font family: **Georgia, serif** (all roles). Weights restricted to **regular (400)** and **bold (700)** only; italic is reserved for flavor/sub-title text (e.g. boss subtitle `'italic 14px Georgia'`) and counts under the body role, not a third weight axis.

## Color

60/30/10 split mapped to the game's established palette. The dominant/secondary surfaces are biome-driven (each biome supplies its own `bg`/`floor`/`wall`); the values below are the **menu / default (non-run) surface** plus the cross-biome accent system. Illustrated assets must sit within each biome's palette and reserve the accent for the listed elements only.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0b0710` (default) / per-biome `bg` (`#160a0e`, `#061412`, `#171107`, `#0a0e16`) | Screen background, deepest surface; biome backgrounds occupy this slot during a run |
| Secondary (30%) | per-biome `floor` (`#241016`, `#0b201c`, `#241b0d`, `#121828`) and `wall` (`#3d1a20`, `#143830`, `#403018`, `#222c4a`) | Floor tiles, walls, panel/overlay surfaces |
| Accent (10%) | `#ffd34d` (divine gold) + per-biome `accent` (`#ff5533`, `#2ee6a8`, `#ffcf5c`, `#9fb8ff`) | See reserved list below |
| Destructive / threat | `#ff4430` (Agni red family: `#ff5533`, `#ff4444`, `#ff2222`) | Boss/enemy threat color, low-HP warning, danger zones, death overlay — never used for friendly/divine elements |

**God identity colors (fixed, do not repurpose):** Hanuman `#ff8c42`, Agni `#ff4430`, Indra `#ffd34d`, Vayu `#7fdcb7`, Krishna `#5c7cff`, Durga `#e84a8a`. These tint each god's boon-card art (ART-05) and must remain distinguishable.

**Rarity colors (fixed):** Common `#cfcfcf`, Rare `#5cb8ff`, Epic `#c77dff`.

Accent (`#ffd34d` divine gold) reserved for:
- Divine Boon reward indicator and boon-card frame highlight
- Selected / focused door or boon choice
- Indra's god identity
- Primary call-to-action emphasis (the "choose / claim" affordance)

Accent is NOT used for: body text, ambient decoration, enemy/threat elements (those use the destructive/threat family), or generic borders.

**Reverence guardrail (color):** Divine/god/boon elements use the gold + god-identity palette; asura/rakshasa/boss threat elements use the red destructive family. This visual line (allies warm-gold/cool-divine vs. enemies aggressive-red) must not be crossed in illustrated art — it encodes the CLAUDE.md mythological-reverence constraint.

## Copywriting Contract

This phase ships no new game-flow screens, but the asset pipeline and its fallback/empty/error states need defined copy (developer-facing and player-facing). Existing in-run flavor copy (e.g. death lines in `js/data.js`) is preserved unchanged.

| Element | Copy |
|---------|------|
| Primary CTA | "Claim Boon" (existing boon-selection affordance; boon-card art must leave room for this label) |
| Empty state heading | (Art not yet generated) — **silent fallback**: render the legacy primitive `draw()` shape. No player-facing empty-state text by design (D-11). |
| Empty state body | Developer-facing only: `console.warn('[SPRITES] atlas missing for "{key}" — using primitive fallback')` |
| Error state | Asset load failure → silent graceful degradation to primitives; developer-facing: `console.warn('SPRITES disabled — fallback to primitives', err)`. No crash, no visible production error (D-11, RESEARCH Pitfall 2). |
| Destructive confirmation | none in this phase — no player-facing destructive actions. (Dev-side: re-packing/overwriting an atlas via `tools/pack-atlas.js` is non-interactive and idempotent; regenerating a deviated sprite is a manual art decision, not a guarded UI action.) |

**AI provenance / disclosure copy (ART-06 / QA-04):**
- Every generated atlas gets a `PROVENANCE.json` entry (schema D-13: filename, prompt, negative_prompt, model, checkpoint, sampler, cfg, seed, generated_date, post_processing[]).
- A draft `assets/sprites/AI-DISCLOSURE.md` states the public disclosure text: art is **AI Pre-Generated** (ships with the game, consumed by players) per Steam's post-Jan-2026 Content Survey. Actual survey submission is deferred to Phase 7 (store page); Phase 2 produces the disclosure-ready record only (RESEARCH Open Question 1).
