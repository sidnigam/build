# Phase 05.4: Epic-Inspired Environment Art Upgrade - Context

**Gathered:** 2026-09-26
**Status:** Ready for planning. The orchestrator made these decisions; the user is away. The planner refined them and locked them below.
**Executes:** AFTER Phase 05.1 (scrolling camera + larger arenas) merges. The runtime plan (05.4-04) has the external dependency `phase 05.1`. The art plans do not touch js/ and can run as soon as 05.4-01 lands.

<domain>
## Phase Boundary

Each of the 4 combat biomes gets a Hades-style layered arena. The layers are a detailed seamless floor, an architectural border, epic-inspired set dressing, obstacles and hazards drawn with biome art, and cheap lighting/atmosphere. The arena sizes come from 05.1 (normal ≈2240x1300, boss ≈1600x960, both read at runtime). Combat must stay readable.

**In scope:** ENV-01..ENV-09 (defined below). Covers checkpoint evaluation, env art tooling, AI generation of the floor tiles, wall kit, props, decals and hazard skins for 4 biomes, a runtime environment renderer (`js/environment.js`), obstacle/hazard art integration, light/atmosphere overlays, readability tuning with screenshots, provenance and AI-disclosure.

**Out of scope:** dynamic lighting, bloom and color grading (Phase 05.6). Character sprite fidelity (05.6). God portraits (05.5). Camera/arena sizing itself (05.1). Hub antechamber art (deferred). Animated props (deferred). Unique non-tiling boss backdrops via Ultimate SD Upscale (deferred). Flux (deferred fallback only).
</domain>

<decisions>
## Implementation Decisions

### Checkpoint (ENV-01)
- **D-01:** The A/B candidate is **DreamShaper XL "alpha2 (xl1.0)"**: Civitai model 112902, version 126688, file `dreamshaperXL_alpha2Xl10.safetensors`, 6.46 GB fp16. Civitai SHA256 is `0F1B80CFE81B9C3BDE7FDCBF6898897B2811B27BE1DF684583C3D85CBC9B1FA4`. Download URL: `https://civitai.com/api/download/models/126688?fileId=91562`. Base model SDXL 1.0. The license is CreativeML OpenRAIL++-M, and the model-level Civitai flags on 2026-09-26 were `allowCommercialUse: [Image, RentCivit, Rent]`. The planner verified these via the Civitai API. The executor MUST re-verify them at download time and record them.
- **D-01a:** The **Lightning / "Turbo-Lightning" / Turbo** DreamShaper variants are EXCLUDED. The Civitai page says the Turbo lineage "cannot be used commercially unless you get permission from StabilityAI", and the Lightning file is labelled Turbo-Lightning. The lineage is not license-clean enough for a commercial Steam release.
- **D-01b:** Disk gate: the dev machine had only about 12 GB free at planning time. Download only if `df` shows ≥ 8.5 GB free, and never delete user files to make room. If the gate fails, the download needs auth (HTTP 401/403), the SHA256 mismatches, or the license text differs, stay on `sd_xl_base_1.0` and record why. That is an allowed outcome, not a blocker.
- **D-01c:** A/B protocol: 2 subjects, a Naraka floor tile and a Ranabhoomi broken-chariot-wheel prop. Each subject gets 2 seeds on each checkpoint, so 8 images, all with identical prompts and sampler settings (dpmpp_2m / karras / 32 steps / cfg 7). Batch by checkpoint to avoid model reload thrash on 16 GB RAM. Compare side by side in one review grid on painterly detail, prompt/framing adherence (top-down tile with no focal point; clean isolated prop silhouette) and artifacts. Adopt DreamShaper only if it wins on ≥ 2 of 3 criteria with no cultural or composition regression.
- **D-01d:** Checkpoints are a catalog in `prompts.json` (`checkpoints.{profile}` = file, label, sampler, scheduler, steps, cfg, source_url, sha256, license). `env_checkpoint` selects the profile for env subjects only. The existing `checkpoint` profile for characters/biomes stays `sdxl_base`, so existing assets and 05.5 are unaffected unless they opt in.

### Layer composition (ENV-02..06)
- **D-02:** World layer order is `[ENV.floorLayer, SPRITES.bridgeSprite, bgContainer{ENV.lightLayer, ENV.structLayer}, entityContainer (+ y-sorted pillar skins), ENV.atmosLayer, fxContainer]`. Stage order is `[worldContainer, ENV.vignette (screen-space), hudContainer]`.
  - floorLayer sits below the bridge, so the existing in-arena readability wash/darken on the bridge still applies. It holds the floor TilingSprites, water bands, the pit abyss, floor decals, hazard base art and a margin shade.
  - The bridge keeps the arena wash, mandala, hazard telegraphs, zones, danger zones, doors and any un-skinned primitive obstacles.
  - lightLayer + structLayer sit above the bridge, so walls and props are not washed. They are pre-graded darker at finish time instead.
  - atmosLayer sits above entities with capped alpha. It holds dust shafts and mist banks.
- **D-02a:** Everything above the bridge that overlaps `GAME.arena` is limited to obstacle skins, which sit exactly on collision footprints, and capped-alpha light/atmos. Nothing else may overlap the playable rect.

### Floor (ENV-02)
- **D-03:** 2 floor tile variants per biome (`floor_a`, `floor_b`). Generate square at 1024x1024 and make seamless in post (`finish_env.py tile`: half-offset + feathered cross-blend). Self-review must look at a 2x2 repeat preview. Runtime: base TilingSprite (seeded choice of a/b, seeded `tilePosition`) plus a macro-variation overlay TilingSprite of the other variant at a larger `tileScale` and alpha 0.25-0.45. Both cover the env frame (arena + pad). `tileScale` comes from the manifest and is tuned so flagstone scale reads right against the ~52px player.
- **D-03a:** Floor decals (3-4 per biome, e.g. ember seams, scorch, moss, puddles, cart ruts) are finished with a difference-key alpha (rembg is poor at flat decals). They are graded to low contrast and scattered 8-14 per room inside the arena with alpha ≤ 0.55. They keep 160px clear of the spawn point, the door column (x > arena right − 120) and obstacles. Mandala/rug inlays are allowed ONLY if purely geometric and non-sacred. Default is none.
- **D-03b:** Existing accepted 02-08 floor prompts/seeds are the starting point for `floor_a`: naraka 41000 cracked basalt, patala 41101 teal-black stone, ranabhoomi 41203 scattered debris, vaitarani 41300 slate river stones. Keep the "seamless repeating texture, evenly scattered" anchor phrasing and avoid radial nouns in floor prompts (02-08 lesson).

### Architecture (ENV-03)
- **D-04:** Wall kit per biome:
  - `wallface`: horizontal seamless strip. Generate 1344x768 elevation, crop the wall band, resize to 1024 wide, make x-seamless.
  - `wallcap`: square seamless top-down coping, 512.
  - `column`: tall cutout, generated 832x1216. Serves as both the north-wall column and the default pillar skin.
  - `gate`: cutout arch/gateway, generated 1024x1024 or 896x1152.
- **D-04a:** Placement is pure and data-driven:
  - The north wall face base is flush with `arena.y`. Face height = min(manifest faceH, pad.top − 24). Columns sit at seeded spacing 260-380px along it and at both corners.
  - West/east: a dimmed raised plinth band (width = pad.side − capT, drawn with a lip line so it reads as not walkable), then a wallcap strip.
  - South: a wallcap lip strip flush below the arena bottom.
  - The west entry gate is centered on the spawn y. An east gate appears behind each door as doors open, rebuilt on door count change.
  - Prop placement reserves gate spans.
- **D-04b:** All sizes derive from `GAME.arena` and the camera padding exposed by 05.1. If 05.1 exposes no padding, `ENV.CFG.PAD = {top: 200, side: 110, bottom: 60}` is the fallback. Elements that don't fit the available pad shrink (face height) or are dropped (side props). Nothing is hard-coded to 1280x720 or 2240x1300.

### Props (ENV-04)
- **D-05:** 6-10 props per biome, cutout via rembg. Epic sources:
  - **Naraka** (Yama's hells, Garuda Purana): `ledger_lectern` (Chitragupta's ledger: an iron/wood lectern with an open palm-leaf ledger, marks illegible, no figure), `scroll_pile`, `iron_cauldron` (Kumbhipaka vat, empty with dim glow, no bodies), `brazier` (light), `chain_post` (post with chains + hooks), `fire_pit` (light), `iron_cage` (empty, broken). Architecture: obsidian/iron walls, obsidian gate with iron bars. Hazard skin: `vent_grate` (round iron floor grate) under fireVent.
  - **Patala** (Naga-loka, Bhogavati): `glow_fungus` (light), `gem_pile` (naga treasure: gems + gold coins), `treasure_urn`, `pool_basin` (stone basin of bioluminescent water, light), `fallen_pillar` (broken column with scale carving), `crystal_rocks`, `bronze_lamp` (light). Architecture: carved serpent-scale walls, **serpent-coiled column** (a single plain serpent body carved around a stone column, NOT a multi-hooded divine Naga), gem-studded arch.
  - **Ranabhoomi** (Kurukshetra, Bhishma Parva): `chariot_wheel` (broken spoked wheel), `chariot_wreck` (overturned war chariot, also the skin for `rana_chariots` walls), `fallen_banner` (fallen dhvaja pole with a tattered plain/geometric pennant), `arrow_cluster` (arrows stuck in ground), `quiver` (spilled arrows), `war_drum` (nagara kettle drum), `conch_stand` (a shankha resting on a drum/stand, upright, never on the ground as a decal), `shield_pile`. Architecture: earthen rampart with a lashed-timber palisade and torn cloth hangings, timber war gate, and a `dhvaja` banner pole used as the pillar skin for `rana_banners`. No gore, no bodies, no deity emblems on banners.
  - **Vaitarani** (river of death): `moored_boat` (empty ferry husk, no passengers), `mooring_post` (also the pillar skin for `vait_posts`), `reeds`, `floating_diyas` (clay lamps on dark water, light; placed only on the south-margin river strip), `rope_coil`, `driftwood`, `stone_marker` (eroded, no inscriptions). Architecture: ghat steps with stone balustrades and mooring rings, stone embankment cap, stone lamp pillar (`lamp_pillar`, lit) as column, ghat landing arch. Extra tile: `water` (dark still river water), used for riverCurrent bands, vaitarani pits and the south river strip. No bones, skulls, pyres or bodies.
- **D-05a:** Prop placement zones: `north` (bases in [arena.y − 14, arena.y − 2], overlapping the wall face), `west`/`east` (on the side plinths, width-limited), `corner` (clusters of 2-4 at NW/NE/SW/SE), `south` (only frames flagged `low`, plus Vaitarani diyas on the river strip). Per room 10-18 prop instances are drawn from the 6-10 kinds, weighted and seeded. No prop's AABB may intersect the arena rect.
- **D-05b:** Scale uses the manifest `worldH` (target on-screen height in world px; the player is ~52px), capped by the zone's available width. This is tuned in 05.4-05.

### Obstacles and hazards (ENV-05)
- **D-06:** Skin mapping lives in the manifest (`skins.pillar|wall|pit` plus `byTemplate` overrides keyed by DATA.LAYOUTS template id).
  - **pillar (circle):** the column/prop sprite goes in entityContainer with zIndex = base y (y-sorted like entities). The base width is fit to 2r×1.1. When a player/enemy is behind it (north of the base, within its horizontal span and below its top), alpha fades to 0.45.
  - **wall (rect):** `@cap` = a wallcap TilingSprite exactly on the rect, a short front face strip (≤ min(28, 0.3h)) below it, and a drop shadow, all in structLayer. Or a prop skin fit to the rect: `chariot_wreck` for `rana_chariots`.
  - **pit:** `@abyss` = a dark radial abyss in floorLayer plus a ring of rim decals. Vaitarani pits use `@water` (the water tile masked to the pit shape and darkened).
  - Hazards: fireVent → `vent_grate` under each vent (floorLayer, under the bridge telegraph). venomPool → a procedural rim plus moss decals. riverCurrent → `@water` band scrolled along the current direction at push speed (surge speed during surge). arrowVolley → no skin (transient markers).
  - `renderObstacles` skips the primitive only for skinned obstacles, so collision is untouched.

### Lighting / atmosphere (ENV-06)
- **D-07:** All light textures are procedural canvases (radial pool, soft beam, mist blob), in the same pattern as the `vfx.js` `emberCv`/`mistCv`. They are not AI. Per-prop `light` in the manifest attaches a pool to a prop (braziers, fire pits, glow fungus, pool basins, lamps, diyas). Biome extras: Naraka faint ember pools in the arena; Patala teal glow pools; Ranabhoomi 2-4 diagonal dust shafts (atmosLayer, additive, slow drift); Vaitarani mist banks along margins (atmosLayer, normal blend, slow drift). A screen-space vignette uses manifest `grade.vignette` (0.3-0.5 edge alpha).
- **D-07a:** Caps: in-arena light/atmos alpha ≤ `ENV.CFG.LIGHT_MAX_IN_ARENA` (0.12). Margin lights may reach 0.4. No dynamic lighting or bloom (05.6).

### Readability guardrails (ENV-07)
- **D-08:** Floor tiles, measured at finish time before the runtime wash: mean luma ≤ 0.45, luma std ≤ 0.15, mean saturation ≤ 0.32. These are calibrated on the accepted 02-08 backgrounds (naraka L 0.27/std 0.09/S 0.25; patala 0.32/0.09/0.25; ranabhoomi 0.53/0.18/0.31 is the known-bright outlier; vaitarani 0.31/0.18/0.23). `finish_env.py` may apply a recorded deterministic grade (contrast compression + saturation scale) to meet limits instead of regenerating.
- **D-08a:** Props/columns/gates/decals get a deterministic finish grade from `prompts.json env_grade`: props sat×0.85/val×0.88, architecture sat×0.8/val×0.82, decals sat×0.7/val×0.8. The runtime `propTint` from the manifest applies on top. Props stay darker and less saturated than characters.
- **D-08b:** Starting in-arena wash values are the quick-260926-dcz ones: BG_FLOOR_TINT 0.55, BG_FLOOR_DARKEN 0.25, BG_DIM_OUTER 0.6. The manifest `grade.floorTint/floorDarken/outerDim` can override per biome. Screenshots (post-wash) must keep central-region floor mean luma ≤ 0.30 and std ≤ 0.12. Telegraph rings (fireVent warn, arrow markers, boss danger zones) must be clearly visible in the combat shots.
- **D-08c:** Screenshot matrix per biome: 3 camera positions (NW corner, center, SE corner with doors open), 1 boss-arena shot and 1 combat readability shot (enemies + an active hazard telegraph). That is 20 shots, reviewed as 4 per-biome grids. Driver: `tools/art/env_shots.mjs`, which reuses `tools/browser-check.mjs` from 05.1 if present, otherwise the CDP approach of the session scratchpad `cdp-check.mjs` (headless Chrome, swiftshader, `python3 -m http.server 8091`).

### Cultural rules (ENV-08, hard rules)
- **D-09:** Nothing on the walkable ground plane may be a deity image, idol, face, yantra/deity-mandala, Om, swastika, trishula, lotus throne or recognizable sacred symbol. That covers floor tiles, water, decals and hazard skins. These roles carry `ground_safe: true`, set only after this is checked. Vertical props/architecture may carry decorative non-figurative carving only. No deity figures anywhere in env art (gods are allies and appear only in 05.5 portraits). Serpent carvings are plain serpent bodies, never multi-hooded divine Nagas. Banners carry plain/geometric designs only. The conch (shankha) appears only upright on a stand, never on the ground. Diyas appear only on water or plinths. No gore, blood, bones, skulls, corpses, pyres or cremation imagery. The chakravyuha formation mandala already drawn on the bridge is an abstract military-formation motif and stays.
- **D-09a:** The global env negative prompt adds: people, person, figure, face, deity, god, goddess, idol, statue, murti, yantra, mandala, om symbol, swastika, trishula, trident, lotus, halo, text, letters, inscription, blood, gore, skeleton, bones, skull, corpse. The self-review checklist gains (j): "ground-plane asset: no face/idol/yantra/sacred symbol; vertical asset: no deity figure".

### Provenance and tooling (ENV-08)
- **D-10:** New provenance kinds:
  - `env-tile`: tiles and wall strips, tracked `*-tile.png` in `assets/sprites/env/{biome}/`.
  - `env-prop`: finished atlas frames at `assets/sprites/_raw/env/{biome}/frames/{biome}_{key}_0.png`, one entry per generated subject with full prompt/seed/checkpoint.
  - `env-atlas`: `{biome}-env-atlas.png`, with a `components` list that must equal the atlas JSON frame names.
  - All env-* entries require `role`, `biome`, `cultural_check` and `ground_safe` (boolean; true is required for ground roles floor/water/decal/hazard-skin). The checkpoint label comes from the sidecar's profile, not a hard-coded constant. The top-level `checkpoint_licenses[]` is added alongside the legacy `checkpoint_license`, which is kept for compatibility.
- **D-10a:** The per-biome build is data-driven. Each `prompts.json env_subjects.{biome}.{key}` entry holds prompt fields plus review state (`accepted_attempt`, `rejected: {seed: reason}`, `self_review`, `cultural_check`, `crop` for wallface). `python tools/art/env_build.py {biome}` then finishes all accepted subjects, writes tiles and frames, packs the atlas (`tools/pack-atlas.js`), writes/merges the manifest and upserts provenance, all idempotently. `gen_batch.py` runs multi-subject generation in the background (resumable). `review_grid.py` makes one labelled grid image per review pass to save context.

### Env manifest (contract between art plans and runtime)
- **D-11:** One manifest per biome at `assets/sprites/env/{biome}/{biome}-env.json`, written by `env_build.py` and read by `js/environment.js`:
```json
{
  "schema": 1, "biome": "naraka",
  "atlas": "assets/sprites/env/naraka/naraka-env-atlas.json",
  "tiles": {
    "floor_a":  { "path": "assets/sprites/env/naraka/naraka-floor-a-tile.png", "size": [1024,1024], "role": "floor", "ground_safe": true },
    "floor_b":  { "path": "assets/sprites/env/naraka/naraka-floor-b-tile.png", "size": [1024,1024], "role": "floor", "ground_safe": true },
```

  - Frame keys map to atlas frames named `{biome}_{key}_0.png` (the pack-atlas `{actor}_{state}_{n}` convention).
  - `size` is the finished frame pixel size, so layout is computable headless.
  - Tokens starting with `@` are procedural/tile skins (`@cap`, `@abyss`, `@water`, `@pool`).
  - `env_build.py` writes the structural fields (paths, size, role, ground_safe, frame names). On re-runs it PRESERVES existing tuning fields (floor/walls/lights/grade blocks and per-frame worldH/worldW/alpha/zones/weight/light/anchor/footW).
  - `ENV.validateManifest(m, {strict})` rejects: unknown role, missing size/frame, ground roles without `ground_safe: true`, and skin references that don't resolve. Strict mode, used for shipped manifests, also requires ≥ 1 column, ≥ 1 gate, ≥ 6 props and ≥ 3 decals.

### Contract with Phase 05.1 (runtime plan must verify first)
- **D-12:** Assumed from 05.1:
  - `GAME.arena` is the world-space playable rect, sized per room from DATA (normal vs boss).
  - CAMERA drives `SPRITES.worldContainer` so world coords = game coords.
  - The legacy world primitives still draw on the bridge (possibly resized/offset by 05.1).
  - The camera clamp allows some world beyond the arena (padding).

  - If 05.1's padding is under ~120px top, the env degrades gracefully (D-04b) and the executor flags it in the SUMMARY for a follow-up padding change in 05.1's constant. It does not edit camera code (outside ownership).

### Performance and fallbacks (ENV-09)
- **D-13:** One atlas per biome (≤ 2048², props finished at ≤ 384px max side, column/gate ≤ 512 tall). Floors and walls are TilingSprites. Env sprites have precomputed world AABBs and toggle `visible` against `viewRect() + CULL_PAD` when the camera moved > 8px. Target ≤ ~120 env display objects per room. `ENV.stats()` reports the counts.
- **D-13a:** Loading is non-fatal (the D-11 lineage): `ENV.ensureLoaded(biome)` lazily loads the manifest, atlas and tiles via `PIXI.Assets` on first use.
  - If the manifest/atlas is missing, the floor falls back to the legacy `bg:{biome}` texture as a TilingSprite, and walls to procedural Graphics (biome.wall color).
  - If that is missing too, the existing primitive renderBackground path runs unchanged.
  - Headless: ENV is inert (`sync` returns false) and all legacy code paths are untouched.

### Process
- **D-14:** ComfyUI serialization: 05.4-01, 05.4-02 and 05.4-03 generate images. They MUST NOT run while a 05.5 portrait-generation executor is active. Before each generation batch, check `GET http://127.0.0.1:8188/queue` has empty `queue_running` and `queue_pending`. The orchestrator serializes these; the plans note it. `prompts.json` edits are confined to the new keys `checkpoints`, `env_checkpoint`, `env_*`. Never reorder or rewrite existing keys, to minimize merge conflict with 05.5.

Tiles/architecture that fail 5 attempts get a prompt rewrite and one more round of 5 before falling back to the 02-08 floor or procedural walls (recorded).
- **D-16:** Human review is non-blocking (Phase 2 D-14a lineage). All new entries are `review_status: "provisional"`. The env contact sheet goes in `assets/sprites/_review/env-contact-sheet.png`.
