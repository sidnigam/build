## Decisions (locked)

- **D-01 Architecture:** one new file `js/music.js` defining global `MUSIC`, loaded in `index.html` and `test/smoke.js`'s file list immediately after `audio.js`. Sections: `MUSIC.theory` (pure data), `MUSIC.gen` (pure generators), `MUSIC.logic` (pure state derivation), `MUSIC.dsp` (pure Float32Array synthesis), then the ctx layer (engine + scheduler). The pure sections must never touch `this.ctx`, `window`, `GAME`, `DATA` or `U` at load time. No new dependencies, no audio asset files, no AudioWorklet/ScriptProcessor: every percussive/plucked timbre is synthesized once in JS into an `AudioBuffer` (rendered at `RENDER_SR = min(ctx.sampleRate, 32000)`) and replayed through disposable `AudioBufferSourceNode`s; the melodic lead is ONE persistent monophonic synth whose params are automated (natural meend, zero per-note node churn).
- **D-02 Polling-only integration (merge-safety with 05.1):** NO edits to `js/game.js`, `js/entities.js`, `js/rooms.js`, `js/ui.js`. MUSIC reads, defensively and read-only, each scheduler tick: `GAME.state` (hub|combat|cleared|choosing|paused|dead|victory), `GAME.prePause`, `GAME.biome.id` (fallback `GAME.biome.droneHz`), `GAME.bossRef` (`.dead`, `.phase`), `GAME.enemies` (count `!e.dead && !e.boss`, loop capped at 200), `GAME.player.hp/maxhp`, `Object.keys(GAME.player.boonRanks).length`, `GAME.player.defiance`. Every read tolerates missing fields. A smoke "polling contract" test fails loudly if 05.1 renames any of these.
- **D-03 Raga / tala map:**

| Context | Raga | Sa (Hz) | Drone | Tala (matras, vibhags) | Matra bpm | Lead | Kit | Character |
|---|---|---|---|---|---|---|---|---|
| Hub | Yaman | 138.59 | Pa | Teentaal 16 (4+4+4+4) | 54 | bansuri | — (no perc.) | serene evening devotion, alap |
| Naraka | Bhairav | 110 | Pa | Rupak 7 (3+2+2, sam is khali) | 104 | bowed (sarangi-like) | tabla | grave, fierce augmented-2nds, andolan on komal Re/Dha |
| Patala | Malkauns | 98 | **Ma** (no Pa in Malkauns) | Jhaptaal 10 (2+3+2+3) | 92 | bansuri (low) | pakhawaj | serpentine, meend-heavy, night |
| Ranabhoomi | Adana | 123.47 | Pa | Ektaal 12 (2x6) | 116 | reed (shehnai-like) | tabla + boosted war drums | heroic, upper-register (vadi = tar Sa), martial |
| Vaitarani | Bhairavi | 82.41 | Pa | Teentaal 16 | 96 | bowed | tabla | tragic farewell, most emotional |

  Biome Sa values equal the existing `DATA.BIOMES[].droneHz`. Full scale/phrase data is specified in 05.3-01-PLAN.md and is canonical Hindustani theory (Adana's vakra komal Ga appears only inside bank phrases, never in free walk).
- **D-04 Tanpura:** replaces the old detuned-sawtooth drone. Four precomputed KS strings with a jawari (amplitude-dependent buzz) term, tuned [first string = droneFirst-12, Sa, Sa, kharaj Sa-12], plucked in the classic 1-2-3-4-rest cycle (0.55 s spacing, 1.1 s rest; 0.7 s spacing in the hub), free-time (not locked to tala), humanized +/-30 ms. A soft persistent sine pad on Sa glues it; a separate sub stem (sine Sa/2 + 35% 2nd harmonic so laptop speakers still hear it) adds chest weight at levels 2-5.
- **D-05 Intensity levels & triggers:**

| Level | Trigger (pure `MUSIC.logic.deriveTarget`) | Texture |
|---|---|---|
| 0 | `state==='hub'` (always Yaman) | tanpura + bansuri alap + swarmandal glisses, no percussion |
| 1 | `cleared`, `choosing`, `victory` | calm biome theme: slow gat, soft tali-only tabla, jor pluck pulse |
| 2 | `combat`, no boss | full theka, mukhda hooks, manjira ching-chak, dhol on vibhags, nagara on sam |
| 3 | combat and (alive non-boss enemies >= 7 or hp/maxhp < 0.30) | + ghost strokes, frequent kayda fills, 8th-note pluck ostinato, dhol every matra; low HP adds heartbeat dhol and a quiet tension-note pad |
| 4 | boss alive, phase 1 | rela 16ths, taans, war drums, tempo x1.15 |
| 5 | boss alive, phase 2 | jhala pluck, dugun mukhda, syncopated dhol, nagara triplet pickups, tempo x1.25 |
| paused | level of `prePause`, `duck=true` | lowpass 1.1 kHz + gain 0.6 |
| dead | `mode='elegy'` | tanpura only after the death stinger |

  Stem gains live in `MUSIC.theory.INTENSITY` (percussion/sub monotonic non-decreasing, drone decreasing). Loudness rule: level 5's summed stem gain may be at most ~2x level 1's (about +6 dB). Intensity comes from density, register, tempo and timbre, not volume.
- **D-06 Transitions:** level UP applies at the next vibhag boundary; level DOWN applies only after the lower target has held >= 3 s, then at the next sam (or the next vibhag if the sam is > 4 s away). Stem gains ramp with `setTargetAtTime` over 1 matra (up) / 2 matras (down). Tempo glides toward target bpm by at most 2 bpm per step (a natural laya acceleration). Raga changes (biome change, hub return) fade all stems out over 1.2 s, swap raga/preset/pad tuning, then restart at step 0 (sam) with a fade in. Buffers for the new raga render during the fade.
- **D-07 Stingers (event → music):** `bossIntro` (bossRef appears): immediate nagara + sub boom, 2.4 s riser, then choir stab + nagara on the first vibhag boundary >= 2.2 s later, forcing level 4. `bossPhase` (phase 1→2): stab + nagara now, reverse-cymbal swell, nagara triplet into the next sam, forcing level 5. `roomClear` (combat→cleared, no boss): immediate nagara + chak, then a tihai (3x phrase, drums + lead cell + big hit on each landing) fitted so the 3rd landing is exactly on the next sam, where level 1 takes over. `bossDefeated`: the same but a longer tihai + stab + temple bell. `reward` (boonCount increases): temple bell on Sa + swarmandal gliss up. `revive` (player.defiance decreases): swell + soft Sa-Pa-Sa' stab. `death` (state→dead): clear queues, fade percussion/pluck/sub in 0.3 s, lead plays a slow avaroha from tar Sa to Sa with meend, soft nagara under the last note, then elegy. `victory`: stab + nagara x3, lead aroha run to tar Sa and sustain, bells, then level 1.
- **D-08 Melody grammar (consonance):** only raga notes; free-walk ascent uses the raga's `up` set and descent its `down` set; max leap 7 semitones except the Sa-Sa' octave, and a leap is followed by stepwise contrary motion; phrases end on a nyas note held >= 1 matra (>= 2 steps in taans); vadi/samvadi weighted x2 in note choice and x1.5 in duration; no note repeated more than 3 times in a row (except in fixed rhythmic motifs); clamped to the raga `range`. Ornaments: meend (glide), kan (35 ms grace from upper raga neighbour), murki (quick turn, level >= 2), andolan (slow +/-25-cent sway on the raga's andolan notes when held >= 1 matra; Bhairav's signature).
- **D-09 Form & long-form variation:** L0 is an alap arc (16-phrase register journey mandra → madhya → tar → madhya, rests of 1-3 matras between phrases). L1-L3 use bandish form A A B A (A = sthayi around madhya, ending on the mukhda landing on sam; B = antara climbing to tar Sa), with every 8th cycle a "breath" cycle in which the lead is tacet while rhythm continues. L4 alternates taans with mukhda, with a tihai every 4 cycles. L5 plays mukhda in dugun, tar-register wails and fast taans. The generator keeps the last 3 phrase signatures and regenerates (up to 3 tries) on a repeat. RNG: seeded mulberry32. The runtime seed is new per run, so each run sounds different while tests stay deterministic.
- **D-10 Humanization:** onset jitter 0..+6 ms for drums/pluck, 0..+10 ms for the lead, +/-40 ms rubato at L0 (always clamped so no event lands before `ctx.currentTime`). Velocity jitter +/-8%. Tali accents +15%, khali vibhag -20%. Tihai landings and stinger hits are NOT jittered.
- **D-11 Mix / bus graph:** per-stem GainNodes (drone, sub, lead, pluck, tabla, big, metal, fx), with StereoPanners on pluck (-0.2), tabla (+0.15), metal (+0.3) and tanpura strings alternating on two panners (-0.35/+0.35). Stems go through per-stem reverb sends into a ConvolverNode (generated stereo IR, 2.4 s, darkening tail), then mix → duck lowpass → duck gain → glue compressor (thr -18 dB, knee 12, ratio 2.5, atk 12 ms, rel 250 ms) → limiter (thr -3 dB, knee 0, ratio 20, atk 2 ms, rel 120 ms) → `OUTPUT_TRIM` → `AUDIO.musicGain` (which stays 0.16 x musicVolume → master, so mute and volume keep working unchanged). Only sine/triangle/PeriodicWave (harmonic rolloff) oscillators are used, all through a note-tracking lowpass. No raw square/sawtooth.
- **D-12 AUDIO integration (only `js/audio.js` edits):** `AUDIO.init()` calls `MUSIC.attach(this)` when a ctx exists. `startDrone(hz)`/`stopDrone()` stay as API-compatible shims (callers in rooms/game/ui stay untouched): they set `currentDrone` and notify MUSIC, and the legacy sawtooth drone code is deleted. Tonal SFX that would clash with the raga key (`death`, `victory`, `roomclear`, `boon`, `defiance`) are skipped while `MUSIC.isAudible()` is true, because MUSIC plays in-key equivalents. When music volume is ~0 or MUSIC is not attached, the SFX play as before.
- **D-13 Settings:** one new key `musicDynamics: 1` (0..1, uses the existing numeric clamp) → `MUSIC.logic.capLevel(level, dyn)` caps the level at `1 + round(4*dyn)` (0 = always calm, for ear-fatigue/accessibility). No UI this phase (index.html is restricted to the script tag). It can be set via `SETTINGS.set('musicDynamics', x)` and gets a slider in a later settings pass.
- **D-14 Debug / audition hook:** `MUSIC.debug(level, ragaOrBiomeId)` forces {level, raga} (bypasses the governor), `MUSIC.debug(null)` clears, `MUSIC.debug()` returns the current state + stats, `MUSIC.debugStinger(name)` fires a stinger. Keyboard chords (hold Backquote + 0-5 level, B cycle raga, S cycle stinger, X clear, P print stats) are installed only when `location.search` contains `musicdebug` or after the first `MUSIC.debug(...)` call. `M` is avoided because it already toggles mute in game.js.
- **D-15 CPU / memory budget:** 25 ms `setTimeout` lookahead loop, 0.12 s schedule-ahead. Average `_tick` < 0.75 ms (3% of the 25 ms period), measured into `MUSIC.stats()`. Voice caps: total ringing one-shots 28; per stem tabla 6, big 4, metal 4, pluck 8, drone 6, fx 4 (over cap → skip, `stats.dropped++`). Bank rendering is sliced (<= 4 ms of jobs per tick) with synchronous fallback counted in `stats.syncRenders`. At most 2 raga banks cached (current + hub).
- **D-16 Headless inertness:** `MUSIC.attach` is reachable only via `AUDIO.init()` with a real ctx. `MUSIC.start()` returns false and schedules no `setTimeout` when `ctx` is null. The main smoke sandbox never has a ctx. Engine/scheduler tests run in a SECOND vm sandbox with a strict `MockAudioContext` (throws on non-finite param values and on `exponentialRamp` to <= 0, and records late `start()` calls and node/edge counts).
- **D-17 Licensing:** 100% procedural synthesis written in this repo, so no third-party audio. MusicGen output (CC-BY-NC) and Stable Audio Open (revenue-capped licence) are rejected. No CC0 samples this phase. The 05.3-03 SUMMARY records this licence statement for the Steam content survey.
- **D-18 File ownership:** `js/music.js` (new), `js/audio.js`, `js/settings.js` (one new DEFAULTS key only), `index.html` (one `<script>` tag only), `test/smoke.js` (add `'music.js'` after `'audio.js'` in `files`, and insert new sections immediately before the final `console.log(failures === 0 ? ...)` summary line). Nothing else. Phase 05.2 also adds DEFAULTS keys / script tags / smoke sections, so keep each edit to a single self-contained hunk to make rebases trivial.
