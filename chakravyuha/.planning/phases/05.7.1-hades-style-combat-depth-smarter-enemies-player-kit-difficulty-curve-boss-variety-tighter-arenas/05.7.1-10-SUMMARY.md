# Phase 05.7.1 Plan 10: Vows of Tapas Hub Panel + Dev-only F4 Summary

**Players who have cleared the game once now get a VOWS OF TAPAS hub button. It opens a 12-card panel where each card shows the vow, its rank pips and the Heat cost of the next rank. Clicking a card (or pressing A on a pad) cycles its rank through `HEAT.setRank`, which saves at once. The header shows the Heat total, the Punya multiplier and the best Heat cleared with each weapon. The next run started from the hub uses the selection. F4 god mode now works only in dev builds: `?dev=1` on the web, or an unpackaged Electron app reported through a new `app:isDev` IPC call.**

## What shipped

- **index.html:** `#btn-vows` sits after `#btn-shrine` in the hub `.menu-btns`. The `#vows` panel (`.panel.solid.hidden`) follows the `#shrine` markup pattern. The CSS adds `.vow-pips`, `.card.vow-card.sworn` and `.vows-best`.
- **UI.hub():** sets `#btn-vows` to `style.display = HEAT.unlocked() ? '' : 'none'`.
- **UI.vows():**
  - The header reads `Heat N · Punya ×1.NN`, with a second line `Best cleared — Khanda — · Gandiva 7 · Gada —`.
  - Each card shows the name with `●`/`○` pips. The description is `desc(rank)`, or `Unsworn — desc(1)` at rank 0. The cost line shows `+N heat` for the next rank, or `max`.
  - `onclick` → `HEAT.setRank(id, (rank + 1) % (ranks + 1))`, then `AUDIO.sfx('click')`, then a re-render.
- **Wiring:**
  - `UI.PAD_HINTS.vows = 'menu'` and `FOCUS.PANEL_BACK.vows = 'btn-vows-back'`.
  - In `GAME.bindButtons`, `btn-vows` opens `UI.vows()` and `btn-vows-back` returns to `UI.hub()`.
- **GAME.devMode():**
  - Returns true for `/[?&]dev=1(&|$)/` on `location.search`, or for `window.chakraNative.isDev === true`.
  - The keydown branch is now `if (k === 'f4' && this.devMode())`. `GAME.godMode` itself is untouched, and tests and `simulateRun` still set it directly.
- **Electron:**
  - `ipcMain.on('app:isDev', (event) => { event.returnValue = !app.isPackaged; })` is registered at module top level, before any window exists.
  - The preload exposes `isDev: ipcRenderer.sendSync('app:isDev') === true`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The shared headless DOM cannot click buttons, list panels or capture keydown**
- **Found during:** Task 1 (RED)
- **Issue:** In the harness DOM stub, `addEventListener` does nothing, there is no `click()`, `document.querySelectorAll` returns `[]`, and every element has the same rect. So the button wiring, `hideAll`, FOCUS navigation and the F4 keydown listener could not be exercised.
- **Fix:** `heatui.test.js` creates its own sandbox with `boot: false` and patches the El prototype and `document` before `GAME.init()`. No change was made to `test/harness.js`, so the other suites are unaffected.
- **Files modified:** test/combat/heatui.test.js
- **Commit:** fd21477

**2. [Test detail] Save check uses STORE, not localStorage**
- In the headless sandbox STORE is in `_memory` mode, so the test checks persistence with `STORE.get(META.KEY)` and a `META.save` call counter.
