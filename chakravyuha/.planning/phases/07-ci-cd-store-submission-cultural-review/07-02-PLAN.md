This plan builds opt-in, anonymous run telemetry (QA-02, 07-CONTEXT D-09). It is a vanilla `fetch` client with no SDK. It is disabled by default at two levels: the endpoint is null, and the opt-in setting defaults to false. It sends one keepalive POST when a run ends, and shows a settings toggle plus a privacy note only when an endpoint exists.

Purpose: the client gives balance data (weapon, biome reached, boons, run time) without collecting personal data. The user picks the endpoint later (07-06). Until then the client is complete and inert.
Output:
- `js/telemetry.js`
- `js/telemetry-config.js`
- the settings, UI and game wiring
- the smoke coverage

  <name>Task 1: TELEMETRY module and config, with headless smoke tests</name>
  <files>js/telemetry-config.js, js/telemetry.js, test/smoke.js</files>
  <behavior>
    - `TELEMETRY.endpoint()` returns null when TELEMETRY_CONFIG is undefined or its endpoint is null, empty, malformed, `ftp:`/`file:`/`javascript:`, or `http:` to a non-local host. It returns the URL string for `https://x.example/ingest`, `http://localhost:8787/ingest` and `http://127.0.0.1/...`.
    - `enabled()` is true only when endpoint() is non-null **and** `SETTINGS.get('telemetryOptIn') === true`.
    - `buildPayload(game, outcome)` returns exactly the keys `[schema, version, outcome, weapon, biomeReached, biomeIdx, boons, runTimeSec]`:
      - `schema` is 1
      - `outcome` is 'death' or 'victory'
      - ids are sanitized to `^[a-z0-9_-]{1,32}$` (otherwise 'unknown')
      - `boons` is `[{id, rank}]`, capped at 64 and sorted by id
      - `runTimeSec` is `Math.round(runTime)`, clamped to 0..86400
      - nothing else is included, even if game has extra fields
    - `onRunEnd` with telemetry disabled makes zero fetch calls (a stub fetch counts them).
    - `onRunEnd` with telemetry enabled makes exactly 1 call:
      - method POST
      - Content-Type application/json
      - `keepalive: true`, `credentials: 'omit'`, `referrerPolicy: 'no-referrer'`
      - the body is the JSON payload
    - A second `onRunEnd` in the same run makes 0 further calls. After `onRunStart()`, the next `onRunEnd` sends again.
    - When fetch throws synchronously, returns a rejecting promise, or is undefined, `onRunEnd` does not throw and returns undefined (never a promise).
    - The settings key `telemetryOptIn` defaults to false. A stored string `'true'` is rejected by the type check.
  </behavior>
