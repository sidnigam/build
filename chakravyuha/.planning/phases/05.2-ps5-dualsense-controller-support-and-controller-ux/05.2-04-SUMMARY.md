# Phase 05.2 Plan 04: Controller Settings, Test Screen & Electron Hardening Summary

**Settings gains a full Controller section (rumble/intensity/aim-assist/pad rebinding/reset) plus a live Controller
Test screen (sticks, triggers, 18-button glyph grid, rumble test, pairing help), and the Electron window now shows,
focuses, and never throttles so a pad-only player gets input and sound immediately on launch.**

## Performance

- **Duration:** ~55 min

- **Completed:** 2026-09-27T12:39Z

- **Files modified:** 4 (`index.html`, `js/ui.js`, `electron/main.js`, `test/smoke.js`)

## Accomplishments

- Settings → CONTROLLER section: Rumble toggle, Rumble Intensity slider, Aim Assist toggle, a 5-row pad rebind
  list (Attack/Special/Dash/Astra/Pause) with live PS/Xbox glyph labels, "RESET CONTROLLER BUTTONS", and a
  "CONTROLLER TEST" entry button — all wired through the existing SETTINGS/PAD persistence layers.
- Pad rebinding is fully live: `UI.startPadRebind(action)` arms `PAD.captureNext`, the next button press rebinds
  and persists via `PAD.saveBindings()` (STORE key `chakravyuha_padbindings_v1`), and the change is reflected in
  glyph hints on the next `GLYPHS.refresh()`.
- New `#ctest` Controller Test screen: live left/right stick dots inside a deadzone ring, L2/R2 fill bars with
  numeric values, an 18-button glyph grid that lights on press (including PS/touchpad when present), a rumble
  test button + status line, a hold-progress bar, and USB/Bluetooth/Steam-Input pairing help shown only while no
  pad is detected.
- `electron/main.js` now creates the window hidden, shows + focuses it on `ready-to-show`, and sets
  `backgroundThrottling: false` / `autoplayPolicy: 'no-user-gesture-required'` so a controller-only player gets
  focused gamepad input and unlocked audio the instant the app opens.
- A full DualSense end-to-end smoke simulation confirms family/model detection, glyph labels, astra casting with
  no menu open, Options-driven pause/resume, and graceful fallback to keyboard/mouse when the pad is unplugged.

## Decisions Made

- Kept `ctestModel`/`ctestHold` pure (state/timer-map in, view-model/action out) so the entire controller test
  screen's logic is headless-testable without a real DOM or `requestAnimationFrame`.
- Isolated the new "disconnected default" `ctestModel` smoke check from the live `PAD.state` object, since an
  earlier plan's fake-navigator poll simulation leaves `PAD.state.connected === true` for the remainder of the
  suite — used an explicit disconnected-shape snapshot instead of touching that pre-existing test's cleanup.
- Rumble test-result text has a 2-second display window before the per-frame loop's generic status label can
  overwrite it, so clicking TEST RUMBLE (or holding △) gives the player a moment to read the result.

## Manual Checks Pending

The following checklist is copied verbatim from `05.2-04-PLAN.md`'s `<human_test_checklist>`. The user runs this
with their PS5 DualSense controllers after execution; results should be recorded here or in a follow-up UAT note.
Non-blocking — execution does not wait on it.

> Setup: `cd chakravyuha && python3 -m http.server 8000` then open http://localhost:8000 in Chrome or Edge (a static
> server is needed; file:// blocks the sprite atlas fetches); `npm run start:desktop` for Electron.
>
> **A. USB, browser (Chrome/Edge)**
> 1. Plug a DualSense in via USB-C, open the game, press any button. Settings → CONTROLLER TEST shows "DualSense · PS · mapping: standard".
> 2. Move both sticks: dots follow; at rest they sit inside the dashed deadzone ring (note any drift).
> 3. Squeeze L2/R2 slowly: bars and values go 0.00 → 1.00.
> 4. Press every button: ✕ ○ □ △ L1 R1 L2 R2 Create Options L3 R3 D-pad PS touchpad each light their glyph (PS/touchpad may be absent on some OS — note which).
> 5. Hold △ 1 s: controller rumbles (or the screen says rumble is unsupported — note which). Hold ○ 1 s: returns to Settings.
>
> **B. Menus with the pad only (no mouse)**
> 6. Hub: D-pad/left stick moves the gold focus ring; ✕ on BEGIN THE ASCENT starts a run. Hub hint line shows PS glyphs.
> 7. Boon pick: holding ✕ while the boon screen appears does NOT pick; release, move, ✕ picks. Shop: ✕ buys, ○ leaves.
> 8. Options pauses; in pause D-pad to SETTINGS, ✕; adjust volume sliders with ←/→; toggle Rumble/Aim Assist with ✕; ○ goes back; Options on pause resumes.
> 9. Hub → Path of Dharma / Armory / Pothi (codex: right stick scrolls) — all usable, ○ returns.
> 10. Die once: death screen RETURN TO THE BANYAN is focused and ✕ works.
>
> **C. Combat**
> 11. Left stick moves; right stick aims — gold arc/chevron circles Abhimanyu, no mouse crosshair; release right stick while moving → aim follows movement.
> 12. R2/✕ attack, L2/□ special, △ astra, ○/R1 dash (dash goes where the left stick points), Options pause. HUD legend shows ○ △ L2/□ glyphs.
> 13. Aim assist on: aim near an enemy snaps and shows a gold diamond; turn it off in Settings and confirm it stops.
> 14. Rumble: light buzz on hits, tick on kills, stronger when hurt, heavy on boss slam / phase change / boss death / your death. Rumble off → nothing; intensity slider changes strength.
> 15. Rebind: Settings → Controller → Astra → press L1 → astra now fires on L1; reload the page → still L1; RESET CONTROLLER BUTTONS restores △.
> 16. Grab the mouse mid-run: crosshair returns, hints switch to keyboard; touch the pad: they switch back to PS glyphs.
>
> **D. Bluetooth**
> 17. Pair a second DualSense over Bluetooth (hold Create + PS until the light bar flashes rapidly; macOS System Settings → Bluetooth). Repeat steps 1–5 and 11–14 over Bluetooth.
> 18. With both pads connected, pressing buttons on either one takes over (test screen "pad N of 2" changes).
>
> **E. Electron**
> 19. `npm run start:desktop`: without clicking the window, press a pad button → focus + input work; music/SFX play without a mouse click. Repeat 1, 6, 11, 14.
> 20. Note anything that differs between browser and Electron, USB and Bluetooth, and macOS/Windows if available.
