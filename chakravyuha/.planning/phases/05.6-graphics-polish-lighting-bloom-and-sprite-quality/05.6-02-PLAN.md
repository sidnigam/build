Implement CONTEXT D-14, D-15 and D-16 as the **pure** part of the light system in js/gfx.js. There must be no Pixi anywhere in this task.

1. **Presets and cap.** Add `LIGHT_PRESETS`, with all D-14 values as tunables, and `CFG.TRANSIENT_CAP = 32`.

2. **Grep the real item shapes before writing adapters.** Check game.js, entities.js and rooms.js for these fields:
   - `pickups` item kind/type and color (boon god color, heal, coin)
   - ring radius and life fields
   - orbit and bolt coordinates. Bolts may be segments, so use their midpoint or each endpoint, capped.
   - zone color and radius
   - door fields, and how "room cleared" is expressed (`GAME.state === 'cleared'`)

   Every adapter skips items without finite x/y.

3. **`collectLights(G, view, tier, envLights)`** returns `{x, y, r, color, a, ground, prio}[]`.
   - Culling: keep a light only if its circle intersects the view rect.
   - Sort by prio descending. For projectiles, the tiebreak is nearest to the player first. Then slice to maxLights.
   - Flicker is computed from a time parameter so it stays pure: `collectLights(..., nowSec)`. Fire uses `a *= 1 - flicker*(0.5+0.5*sin(t*11+x*0.07)*sin(t*7.3+y*0.05))`.

4. **Registry:** `addLight(opts)`, `removeLight(h)`, `_registry` (a Map), `_roomKey`, and `_roomTick(G)`. `_roomTick` computes the key per D-15 and drops `scope:'room'` entries when it changes.

5. **Transients:** `pulse(x, y, kind, color)` and `tickTransients(dt)`. Pulses use an ease-out decay, and the transient list has a fixed cap.

6. **`envPropLights()` contract stub:** return `[]` when `typeof ENV === 'undefined'`. Task 2 fills in the runtime reading.

7. **js/sprites.js:** add `addLight(opts)` and `removeLight(h)` delegates next to `setBackground`. They return `null` or no-op when GFX is absent.

8. **test/smoke.js:** APPEND checks for every behavior above. Build fake `G` objects; never touch the real GAME arrays. Reload gfx.js only if the block needs a fresh state; otherwise reset `GFX._registry` and the transients.
