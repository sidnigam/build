# Phase 05.5 Plan 03: Boon Portrait Panel + Typewriter Dialogue + Codex Gods Summary

**Boon-pick screen now presents the offering god with a slide-in/bob/glow portrait (or symbol fallback), a setTimeout-driven typewriter dialogue box skippable by click/✕/Enter/Space/Esc, duo co-voicing with a partner inset, death/victory memory for next-run callbacks, and a new "Devas Who Answer" section in THE POTHI — plus a 05.2 FOCUS integration so a held/armed ✕ skips dialogue instead of prematurely picking a dimmed card.**

## Accomplishments

- `#boonpick` gains `#god-portrait-wrap` (CSS-drawn `--svg-mandala` aura tinted per-god, primary portrait, partner inset for duo offers) and `#god-dialogue` (speaker/text beats, ✕ skip button, GLYPHS-driven "to continue" hint), plus a new `<style id="gods-css">` block (entry slide-in, `prefers-reduced-motion`-gated idle bob/aura spin, `.cards.awaiting` dimming, THE POTHI's `.codex-god*` styles). The pre-existing unnamed `<style>` and `settings-css` blocks are untouched; `gods-css` sits between `settings-css` and the 05.2 `controller-css` (the plan's own verify script assumed only 2 prior style blocks — outdated since 05.2 shipped `controller-css` first; adjusted the check accordingly, noted below).
- `js/ui.js` new self-contained methods: `preloadGodPortraits`, `presentGod`, `clearGodPresence`, `typeGodDialogue`, `skipGodDialogue`, `_finishTalk`, `godDialogueBusy`, `bindGodDialogueKeys`, `noteGodRunEnd`, `renderCodexGods`, plus the internal `_dlg()` helper. One-line hooks only in existing methods: `offerBoon` (suppress the old inline greet when DIALOGUE is present, call `presentGod`), `offerAmrit` (`clearGodPresence`), `death`/`victory` (`noteGodRunEnd`), `codex` (`renderCodexGods`).
- Typewriter: 3 chars/33ms tick, 350ms inter-beat pause, `setTimeout`-only, token-guarded against stale ticks after skip/re-open; reduced-motion shows text instantly; skip triggers are a panel click, the ✕ button, and Enter/Space/Esc (bound once). Cards are never JS-gated — `.awaiting` only sets `pointer-events:none` in CSS, so smoke's `cards[0].onclick()` and 05.2's `FOCUS.confirm()` still work by direct invocation (the latter needed an explicit redirect, see below).
- Missing/unloaded portraits fall back to the existing `.god-sym` symbol automatically (`_portraitOk[id]` starts `undefined`); duo offers show co-voiced beats from both gods and a small partner-god inset (shown only once that god's own portrait has separately loaded).
- Death and victory now call `DIALOGUE.noteRunEnd(...)` with the run's biome/boss/result, so next run's first meeting with each god can reference it.
- THE POTHI opens with "The Devas Who Answer": met gods show a thumbnail (or symbol), name, Devanagari, epithet, `DIALOGUE.LORE[id]` paragraph + source, and a meeting count; unmet gods show an anonymous "Not yet met" row — implemented with `classList.add`/`remove` throughout (not `className` string concatenation) so the headless DOM stub's `classList.contains` checks (and the game's own CSS class checks) stay correct.
- **Orchestrator integration:** `js/focus.js`'s `tickPad` now redirects an armed ✕ confirm-edge to `UI.skipGodDialogue()` while `#boonpick` is the active panel and `UI.godDialogueBusy()` is true, instead of calling `FOCUS.confirm()` (which would otherwise `.click()` a still-dimmed card programmatically, bypassing the CSS `pointer-events:none` gate). Still inside the existing `this.armed` gate, so the 05.2-02 held-button guard is preserved; cards become the confirm target again once dialogue completes. A new `#god-dialogue-hint` span shows `GLYPHS.html('confirm') + ' to continue'` while typing (hidden when GLYPHS isn't loaded, e.g. the pre-dialogue.js full-run sims in smoke, or once the dialogue finishes).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — blocking issue] `window.DIALOGUE` export added to dialogue.js so ui.js can reliably detect it**
- **Found during:** Task 2, writing the RED smoke behavior block
- **Issue:** `test/smoke.js` (by design, per Plan 02's D-12) exercises many full-run simulations *before* `dialogue.js` is ever loaded into the shared vm sandbox, and those simulations already call `UI.offerBoon`/`presentGod` many times while `DIALOGUE` is genuinely undeclared. Once V8 has resolved and (after enough calls) optimized a bare `typeof DIALOGUE` / direct `DIALOGUE` reference inside an already-compiled function to "not found," that resolution stays permanently stale for that function even after a *later*, separate `vm.runInContext` call declares `const DIALOGUE = {...}` — confirmed empirically (20,000 warm-up calls before declaring the const permanently "poisons" the free-variable lookup, while a plain dynamic property read on the always-present `window`/`globalThis` object does not have this problem). This only manifests inside the smoke harness's specific load order; real play is unaffected because `index.html` loads `dialogue.js` before `ui.js` even parses. Left unfixed, every new god-presence method that checked `typeof DIALOGUE` would silently behave as if DIALOGUE never loaded for the rest of the smoke run, once *any* earlier full-run sim had triggered a boon offer (which they all do).
- **Fix:** `js/dialogue.js` now also does `if (typeof window !== 'undefined') window.DIALOGUE = DIALOGUE;` right after the engine object literal (harmless, additive — the lexical `const DIALOGUE` is unchanged and still what `test/smoke.js`'s own freshly-compiled script blocks reference directly). `js/ui.js` reads it via a new `UI._dlg()` helper (`window.DIALOGUE` property lookup, immune to the staleness) instead of bare `typeof DIALOGUE` checks, in every one of the new god-presence methods.
- **Files modified:** `js/dialogue.js` (1 line), `js/ui.js` (guard pattern only, no behavior change)
- **Verification:** Full `node test/smoke.js` green, including a temporary bisection (later removed) that reproduced the failure precisely at the point in the file where full-run sims first exercise `offerBoon` before `dialogue.js` loads, and confirmed the fix resolves it.
- **Committed in:** `8012a79`

**2. [Rule 1 — bug] `renderCodexGods` used `className` concatenation instead of `classList.add` for the conditional `unmet` class**
- **Found during:** Task 3, writing/running the codex smoke block (all 6 rows showed as "met")
- **Issue:** `row.className = 'codex-god' + (isMet ? '' : ' unmet')` sets the plain string property; the headless DOM stub's `classList` is a separate object that isn't synced from `className` assignments (only from `.add`/`.remove` calls), so `.classList.contains('unmet')` — used both by my own smoke assertions and by the game's actual CSS-class-based logic elsewhere — never reflected it.
- **Fix:** `row.className = 'codex-god'; if (!isMet) row.classList.add('unmet');` — correct in both the stub and a real browser (where `classList.add` also updates `className`).
- **Files modified:** `js/ui.js`
- **Verification:** `node test/smoke.js` — "codex gods section" block green (exactly 2 met rows, 4 unmet, correct thumbnail/lore/"Not yet met" text).
- **Committed in:** `9c1b6d8`
