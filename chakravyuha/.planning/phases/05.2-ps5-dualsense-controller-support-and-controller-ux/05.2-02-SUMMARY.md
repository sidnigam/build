# Phase 05.2 Plan 02: Glyphs, spatial menu focus, pad hints Summary

**New `GLYPHS` (device/family-aware control-glyph tokens with colored PS face-button badges) and `FOCUS` (virtual-focus spatial menu navigation with a held-button "armed" guard) are wired into `PAD.poll()` and every panel now carries a live, device-aware control hint — so a DualSense player sees PlayStation prompts everywhere and can drive the hub, boon pick, shop, shrine, armory, codex, pause, settings, death and victory screens with D-pad/left-stick + ✕ + ○ alone, with no risk of a held combat button auto-confirming a freshly opened panel.**

## Accomplishments

- `GLYPHS.padToken(btn, family)` classifies every one of `PAD.BUTTON_NAMES` into a PlayStation label
  (✕/○/□/△ with `shape`+`kind` for colored canvas/CSS rendering, L1/R1/L2/R2/L3/R3/Options/Create/
  Touchpad/PS) or an Xbox/generic label (A/B/X/Y/LB/RB/LT/RT/LS/RS/View/Menu/Xbox); `keyLabel`
  normalizes keyboard key names (Space/Esc/arrows/Shift/Ctrl/Enter/Tab, single chars uppercased).
- `GLYPHS.tokensFor(action, device?, family?)` resolves any of `move/aim/scroll/navigate/adjust/
  confirm/back` plus the five rebindable actions (`attack/special/dash/cast/pause`) to an array of
  tokens — for pad it reads `PAD.bindings` (falling back to `PAD.DEFAULT_BINDINGS`), for kbm it reads
  live `INPUT.bindings` (so a keyboard rebind changes the hint immediately), with `move` collapsing
  `w/a/s/d` into a single `WASD` token when all four are single letters.
- `GLYPHS.html`/`GLYPHS.hint(key)` build the `<span class="glyph …">` markup for every panel's hint
  line (hub, menu, boon, shop, pause, settings, codex, continue, ctest); `GLYPHS.signature()` +
  `GLYPHS.refresh(force)` re-render every `[data-glyph-hint]` element and toggle `body.pad-mode`
  only when device/family/bindings actually change. `GLYPHS.drawTokens` draws the same tokens as
  canvas badges (vector cross/circle/square/triangle in their classic colors) for the future HUD/
  controller-test screen.
- `FOCUS.pickNext(rects, cur, dir)` is a pure half-plane spatial scorer (primary-axis distance + 2×
  orthogonal distance, no wrap) validated against vertical lists, card rows, and a centered LEAVE
  button below a card row. `FOCUS.navRepeat` gives first-press-fires-immediately + 0.35 s initial
  delay + 0.12 s repeat; `FOCUS.dirFromPad` prefers D-pad over the left stick (0.5 threshold,
  dominant axis); `FOCUS.armStep` is the pure "armed" guard that keeps a panel that just opened from
  reacting to a face button already held from combat, until every face button has been released once.
- `FOCUS.tickPad(state)` drives it all: finds the last visible `.panel`, builds its focusable items
  (`button, .card, input[type=range], input[type=checkbox], select`, excluding `#btn-wipe` and
  anything with zero client rects), remembers per-panel last-focused index, moves the `.pad-focus`
  ring with D-pad/stick, adjusts ranges/selects with left/right, confirms (✕) — checkbox toggle,
  select cycle, button click — and backs out (○) via `FOCUS.PANEL_BACK`. The controller-test screen
  (`ctest`) is wired as a pass-through panel (`FOCUS.PASSTHROUGH`) that consumes pad input without
  navigating, ready for Plan 04. All DOM access is guarded so the same code runs in the headless
  smoke stub.
- `PAD.poll()`: first line now calls `GLYPHS.refresh()` unconditionally (so a mouse click or key
  press mid-pad-session also flips glyphs back to keyboard); immediately before the combat/pause
  dispatch block, a `FOCUS.tickPad(this.state)` gate consumes pad input as menu navigation whenever
  a panel is visible, updating `_prevPressed` before returning so no phantom edge leaks into combat.
- `UI.ensurePadHints()` (additive, one-time) appends a `.pad-hint` div (`data-glyph-hint` set via
  `setAttribute` when available, else a plain `dataset` fallback for the headless stub) into every
  panel except the hub (which already has its own inline, always-visible controls line). `UI.hub()`
  calls it once and refreshes `GLYPHS` after updating its live text.
- `index.html`: `js/glyphs.js` and `js/focus.js` load after `js/gamepad.js`; a new `#controller-css`
  style block holds `.glyph`/`.glyph.g-face`/face-color classes, the `.pad-focus` gold ring + card
  lift + button tint, `.pad-hint` (hidden unless `body.pad-mode`), and `#settings` made vertically
  scrollable; the hub's controls text is wrapped in `<span id="hub-controls-text"
  data-glyph-hint="hub">`.

## Decisions Made

See `key-decisions` in frontmatter. Summary: device/family resolution always falls back to live
`INPUT.device`/`PAD.family` so `GLYPHS.refresh()` can re-render everything from one signature check;
the FOCUS menu gate reuses `poll()`'s existing `INPUT.device === 'pad'` branch rather than adding a
redundant condition; the hub intentionally has no `.pad-hint` footer (it already has an inline,
always-visible hint); `ctest`'s back-button id and pass-through/scroller wiring are already in place
so Plan 04 only needs to add the panel markup.
